# ТЕХНОРЕБУТ — Резервное копирование и Восстановление (Web UI)

Автономный веб-механизм резервного копирования и восстановления системы ТехноРебут (Stage 07B-R2).

Все операции по созданию и восстановлению резервных копий выполняются **исключительно через защищенный веб-интерфейс панели управления** и доступны **только Владельцу системы (OWNER)**. Доступ к терминалу или запуск скриптов командной строки от владельца не требуется.

---

## 1. Пошаговая инструкция для Владельца (Web UI)

### 1. Вход в систему
1. Откройте веб-браузер и перейдите по адресу:
   ```text
   https://localhost:8443
   ```
2. При запросе браузера выберите ваш клиентский сертификат **Владельца (OWNER)**.
3. В верхней навигационной панели нажмите на раздел **«Резервные копии»** (или перейдите напрямую по адресу `https://localhost:8443/backups`).

---

### 2. Создание и скачивание резервной копии
1. В секции **«Создание резервной копии»** нажмите кнопку:
   ```text
   [ Скачать резервную копию ]
   ```
2. Сервер сформирует транзакционно-согласованный архив и автоматически передаст его на скачивание.
3. В вашей папке загрузок появится файл с именем вида:
   ```text
   TECHNOREBOOT_BACKUP_YYYY-MM-DD_HHMMSS.zip
   ```
4. Сохраните этот файл на внешний накопитель (флешку или внешний диск) для безопасного хранения вне сервера.

---

### 3. Восстановление системы из резервной копии
> [!WARNING]
> Восстановление перезаписывает текущую базу данных, фотографии товаров и реестр сертификатов состоянием из выбранной резервной копии.

1. В секции **«Восстановление из резервной копии»** нажмите кнопку **«Выберите файл»** и укажите ранее сохраненный ZIP-архив бэкапа.
2. Нажмите кнопку:
   ```text
   [ Восстановить систему ]
   ```
3. В появившемся диалоговом окне подтвердите операцию.
4. Дождитесь завершения восстановления (отобразится индикатор выполнения).
5. По завершении система покажет уведомление об успешном восстановлении с перечнем восстановленных таблиц и компонентов.
6. Вы можете сразу продолжить работу — перезапуск сервера или перевыпуск сертификата Владельца не требуется.

---

## 2. Состав резервной копии

Резервная копия упаковывается в единый ZIP-архив и включает в себя только изменяемые пользовательские данные, необходимые для полного восстановления состояния системы:

1. **База данных SQLite (`database/`):**
   - `technoreboot.db`: Транзакционно-согласованный снимок базы данных SQLite (созданный через `sqlite3.Connection.backup()`).
   - `technoreboot_dump.sql`: Логический SQL-дамп всех таблиц и записей (`.iterdump()`).
2. **Медиа-файлы и фотографии товаров (`storage/`):**
   - Каталог `product_photos/` со всеми загруженными фотографиями товаров и запчастей.
3. **Безопасность и mTLS PKI (`auth/`):**
   - Корневой CA: `ca/ca.crt`, `ca/ca.key`.
   - Сертификаты и ключи шлюза: `server/server.crt`, `server/server.key`.
   - Сертификаты и ключи Владельца: `certificates/owner.crt`, `owner.key`, `owner.p12`.
   - Клиентские сертификаты пользователей: `.crt`, `.key`, `.p12`.
   - Реестр доступа: `registry.json` со всеми отпечатками, серийными номерами и статусами (включая REVOKED).
   - Защищенный пароль архива Владельца: `owner_password.txt`.
4. **Модуль Авито (`avito-module/`):**
   - Данные интеграции, профили и история парсинга (если присутствуют).
5. **Манифест резервной копии (`manifest.json`):**
   - Версия формата (`1.0`).
   - Метка времени создания (UTC).
   - Ветка Git и хеш коммита.
   - Количество таблиц и строк в базе данных.
   - SHA-256 отпечатки корневого CA и сертификата Владельца.
   - Число активных и отозванных сертификатов в реестре.

---

## 3. Что исключено из архива

В целях безопасности и компактности бэкапа из архива **полностью исключены**:
- Исходный код проектов (`core/`, `admin-shell/`, `gateway/`, `modules/`).
- Образы Docker и слои контейнеров.
- Служебные каталоги Git (`.git/`).
- Тесты, виртуальные окружения и временные файлы кэша (`__pycache__`, `.pytest_cache`).

---

## 4. Безопасность и целостность

1. **Строгое разграничение прав:**
   - Страница `/backups` и API-эндпоинты `/admin-api/backups/download` и `/admin-api/backups/restore` доступны **только** при предъявлении валидного сертификата Владельца (OWNER).
   - Обычные пользователи и неавторизованные клиенты получают ошибку `403 Forbidden`.
2. **Предварительная валидация загружаемого архива:**
   - Перед внесением каких-либо изменений на сервере загруженный файл проверяется на целостность ZIP-структуры (`testzip()`), наличие и корректность `manifest.json`, а также наличие критических файлов (`technoreboot.db`, CA, сертификаты).
   - В случае выявления повреждений операция отклоняется со статусом `400 Bad Request`, а текущие данные остаются нетронутыми.
3. **Бесшовное сохранение сессии Владельца:**
   - После восстановления из валидного бэкапа корневой CA и сертификат Владельца сохраняют идентичность, позволяя Владельцу продолжать работу в текущей сессии браузера без дополнительных настроек.
