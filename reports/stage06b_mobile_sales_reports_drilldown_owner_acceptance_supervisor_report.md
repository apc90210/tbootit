## 2. Архитектура и инженерные решения

### 2.1. Иерархия навигации Drill-down
1. **«Сегодня» (`TODAY`)**:
   - Карточка сводки за сегодня (выручка, чеки, средний чек, наличные / карта / перевод).
   - Прямой список чеков за сегодня (`ReceiptCard`).
   - Клик по чеку открывает отдельный экран чека (`ReceiptDetailScreen`).
2. **«Неделя» (`WEEK`)**:
   - Карточка сводки за текущую календарную неделю.
   - Список дней недели с продажами (`DaySummaryCard`), отсортированный от новых к старым (дата, локализованный день недели, количество чеков с правильным склонением, выручка, типы оплат).
   - Клик по дню открывает отдельный экран чеков дня (`DayReceiptsScreen`).
   - Клик по чеку открывает `ReceiptDetailScreen`.
3. **«Месяц» (`MONTH`) — СТРОГО прямой список дней**:
   - Карточка сводки за текущий календарный месяц.
   - **Напрямую плоский список дней месяца** с продажами (`DaySummaryCard`), без группировки по неделям.
   - Клик по дню открывает экран чеков дня (`DayReceiptsScreen`).
   - Клик по чеку открывает экран детального чека (`ReceiptDetailScreen`).
4. **«Год» (`YEAR`)**:
   - Карточка сводки за текущий календарный год.
   - Список месяцев года с продажами (`MonthSummaryCard`), отсортированный от новых к старым.
   - Клик по месяцу открывает экран месяца (`MonthDaysScreen`) со списком дней этого месяца.
   - Клик по дню месяца открывает экран чеков дня (`DayReceiptsScreen`).
   - Клик по чеку открывает детализацию чека (`ReceiptDetailScreen`).

### 2.2. Симметрия навигации «Назад» и сохранение состояния
- В `MobileApp.kt` реализован механизм отслеживания родительских маршрутов:
  - `monthDaysParentScreen`: запоминает возврат в `MAIN` с активной вкладкой `YEAR`.
  - `dayReceiptsParentScreen`: динамически определяет родителя — либо `MAIN` (если открыто из вкладки «Неделя» или «Месяц»), либо `REPORT_MONTH_DAYS` (если открыто из годового отчета через месяц).
  - `receiptDetailParentScreen`: определяет возврат либо в `REPORT_DAY_RECEIPTS`, либо в `MAIN` («Сегодня»), либо в `POS_TERMINAL`.
- In-memory кэши `monthDaysCache` и `dayReceiptsCache` хранят загруженные данные и предотвращают повторные сетевые запросы при шаге «Назад», исключая мерцание и сохраняя позицию прокрутки `LazyColumn`.

   - Реализована серверная математическая агрегация структур `days` (дни с продажами) и `months` (месяцы с продажами) с расчетом суммы, количества чеков и вложенной разбивки по типам оплаты (`payment_methods`).
   - Добавлена русская локализация дней недели (`Понедельник`, `Вторник`, ...) и месяцев (`Октябрь 2026`, ...).
   - Сохранен строгий бухгалтерский инвариант: сумма по дням/месяцам и типам оплат строго сходится с `revenue_total` родительского отчета.

     - Корректность схем `today`, `week`, `month`, `year`.

     - Корректность фильтрации за конкретный день через `period="custom"`.
     - Отклонение невалидного формата дат (400/422).
     - Поведение при пустом периоде.

## 4. Клиентская реализация (Android / Jetpack Compose)

1. **Модели данных (`SalesReport.kt`)**:
   - Созданы data class `DayReportSummary` и `MonthReportSummary`.
   - В enum `Period` добавлен вариант `CUSTOM("custom", "За период")`.
   - Модель `SalesReport` дополнена полями `days: List<DayReportSummary>` и `months: List<MonthReportSummary>`.
2. **Сетевой клиент (`MobileApiClient.kt`)**:
   - Метод `getSalesReport(period, dateFrom, dateTo)`: лексикографическая сортировка параметров запроса через `RequestBinding.canonicalizePath` для гарантированного совпадения хэша при валидации TRMOBILE1 PoP на сервере.
3. **Локализация и форматирование (`ReportFormatters.kt`)**:
   - Реализована функция `formatReceiptCount(count)` со строгим склонением русских существительных (1 чек, 2–4 чека, 5–20 чеков, 21 чек, 24 чека и т.д.).
4. **Пользовательский интерфейс**:
   - **`DayReceiptsScreen.kt`**: отдельный экран чеков дня с карточкой сводки дня, бейджами оплат и списком чеков `ReceiptCard`.
   - **`MonthDaysScreen.kt`**: отдельный экран дней месяца с карточкой сводки месяца и списком дней `DaySummaryCard`.
   - **`SalesReportScreen.kt`**: обновлен главный экран с одноуровневыми секциями под каждой вкладкой периода.
   - **`MobileApp.kt`**: добавлены маршруты `AppScreen.REPORT_MONTH_DAYS` и `AppScreen.REPORT_DAY_RECEIPTS`, стек родителей и обработчики аппаратного `BackHandler`.
5. **Модульные тесты (`SalesReportDrilldownTest.kt` + `SalesReportTest.kt`)**:
   - Покрытие парсинга вложенных структур, валидации равенства сумм, русских склонений чеков и канонизации URL.
   - **Результат `testDebugUnitTest`:** **159 из 159 тестов пройдены успешно (0 failures)**.
