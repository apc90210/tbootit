## 3. Доказательство устранения первопричины потери фото

### Причина сбоя:
В `chrome-extension/technoreboot-avito/content.js` в список `cardSelectors` входил шаблон:
```javascript
'[data-marker^="item-"]'
```
На реальных страницах кабинета Avito атрибут `data-marker="item-title"` или `data-marker="item-price"` находится на внутренних дочерних элементах карточки. Метод `document.querySelectorAll()` находил первым именно элемент заголовка или цены:
1. `parseListingCardElement(el)` вызывался на элементе заголовка.
2. Внутри элемента заголовка нет тега `<img>` с фотографией товара.
3. Из ссылки извлекался `avito_id`.
4. Функция добавляла `avito_id` в `seenIds`.
5. Когда итератор доходил до родительского контейнера карточки `iva-item-root` (где находилось настоящее фото), карточка пропускалась из-за `seenIds.has(avito_id)`.
6. В результате объявление уходило на сервер без фото (`thumbnail_url: null`).

### Реализованное исправление:
1. **Функция `findCardContainer(node)`:**
   - Поднимается по DOM через `node.closest(...)` по селекторам контейнеров карточек: `iva-item-root`, `[data-marker="item"]`, `[data-marker*="snippet"]`, `[class*="item-root"]`, `[class*="iva-item"]`, `article`, `li`, `tr`.
   - Если прямой `closest` не сработал, поднимается циклом вверх до 12 уровней родительских узлов, находя границу карточки.
2. **Гарантированное восхождение в `parseListingCardElement(cardEl, fallbackAnchor)`:**
   - В самом начале функции выполняется:
     ```javascript
     const container = findCardContainer(baseNode) || baseNode;
     ```
   - Все операции поиска фото (`<img>`, `<picture>`, `source`, background-image) производятся строго внутри полного контейнера `container`.
3. **Удаление вредного селектора из `extractMyListingsData()`:**
   - Селектор `[data-marker^="item-"]` полностью удален из перечня селекторов поиска карточек.
   - Использована структура `itemsById = new Map()`. При обнаружении того же `avito_id` карточка не отбрасывается, а обогащается найденным фото или уточненной ценой.

## 4. Поддержка всех актуальных паттернов разметки Avito

В `content.js` реализован мульти-паттерный механизм с приоритетами:

| № | Источник / Паттерн разметки | Описание и логика выбора | Статус |
|:---:|---|---|:---:|
| **1** | `<picture><source srcset="...">` | Парсинг `srcset`, извлечение самого качественного дескриптора (например, `640w` или `2x`). Нормализация протокола (`//...` -> `https:...`). | **ПОДДЕРЖАНО** |
| **2** | `img.currentSrc` | Чтение активного загруженного URL из свойства браузера. | **ПОДДЕРЖАНО** |
| **3** | `img[data-srcset]`, `img[srcset]` | Обработка адаптивных наборов изображений с выбором наибольшего разрешения. | **ПОДДЕРЖАНО** |
| **4** | `img[data-src]`, `img[data-origin-src]` | Извлечение ссылок для lazy-loading изображений Avito. | **ПОДДЕРЖАНО** |
| **5** | `img[src]` | Прямая ссылка на изображение. | **ПОДДЕРЖАНО** |
| **6** | CSS `background-image` | Извлечение `url('...')` из inline-стилей превью-блоков. | **ПОДДЕРЖАНО** |
| **7** | **Фильтрация паразитных картинок** | Исключение элементов и URL, содержащих `avatar`, `user-avatar`, `seller-avatar`, `logo`, `badge`, `.svg`, `placeholder`, `data:image/svg+xml`. Аватары продавцов и логотипы магазинов никогда не выбираются как фото товара. | **ПОДДЕРЖАНО** |

## 5. Диагностика в интерфейсе расширения (Popup UI)

В попап расширения (страницы активного кабинета Avito) добавлены:
1. **Индикатор «Фото найдено: X из N»**:
   - Зеленый бейдж (`badge-success`), если `X === N` (все фото найдены).
   - Синий бейдж (`badge-info`), если `0 < X < N` (найдена часть фото).
   - Красный бейдж (`badge-error`), если `N > 0`, а `X === 0`.
2. **Предупреждающий баннер**:
   - Если на странице обнаружены объявления (`N > 0`), но ни у одного не найдена миниатюра (`X === 0`), отображается информационный блок:
     `⚠️ На странице найдено N объявлений, но ни у одного не найдено фото. Рекомендуется прокрутить страницу вниз, чтобы загрузились превью.`

## 6. Сквозная цепочка прохождения фото

Цепочка доставки и отображения изображения подтверждена сквозными тестами:
```
[DOM Avito] -> content.js (findCardContainer + multi-source photo extractor)
     ↓
[Service Worker] -> service_worker.js (BulkImportPayload: items with thumbnail_url & base64)
     ↓
[Avito Module] -> /admin-api/avito-extension/bulk-import (extension_bridge.py)
     ↓
[Core Module] -> POST /products/bulk-avito-import (avito_import_service.py)
     ↓
[Файловая система] -> /data/storage/product_photos/{id}_{hash}.jpg
[База данных] -> таблица product_photos (sort_order=0, media_url=/media/product_photos/...)
     ↓
[Gateway mTLS] -> GET https://localhost:8443/media/product_photos/... -> HTTP 200 OK (image/jpeg)
     ↓
[Admin Shell / Inventory] -> GET /inventory/products -> рендерит <img src="..." alt="Превью">
```

## 9. Инструкция для Владельца по браузерной приемке

> [!IMPORTANT]
> **Приемка осуществляется СТРОГО В БРАУЗЕРЕ (БЕЗ ТЕРМИНАЛА, БЕЗ КОМАНДНОЙ СТРОКИ И БЕЗ CLI)!**

### Шаг 1: Обновление расширения в браузере Chrome
1. Откройте в браузере с установленным сертификатом владельца страницу:  
   `https://localhost:8443/avito/extension`
2. Убедитесь, что на странице указана версия **v0.2.52**.
3. Нажмите кнопку **«Скачать расширение (ZIP, v0.2.52)»**.
4. Распакуйте скачанный архив `technoreboot-avito-extension-0.2.52.zip` в удобную папку на компьютере (или замените файлы в ранее распакованной папке расширения).
5. В браузере перейдите на страницу:  
   `chrome://extensions`
6. Включите «Режим разработчика» (в правом верхнем углу).
7. Нажмите иконку **🔄 (Обновить)** на карточке расширения «ТехноРебут: Интеграция Авито» (или нажмите «Загрузить распакованное расширение» и выберите новую папку).
8. Убедитесь, что версия расширения стала **0.2.52**.

### Шаг 2: Проверка сопряжения и попапа расширения
1. Нажмите на значок расширения «ТехноРебут» в панели расширений Chrome.
2. В окне плагина проверьте версию в подвале: **v0.2.52**.
3. Если статус «Сопряжено»: переходите к следующему шагу. Если нет: нажмите «Сгенерировать код» на `https://localhost:8443/avito/extension`, введите код в расширение и нажмите «Подключить».

### Шаг 3: Проверка диагностики фото на странице кабинета Avito
1. Откройте вкладку с вашим кабинетом объявлений Avito (`https://www.avito.ru/profile/items` или публичный профиль продавца).
2. Откройте попап расширения «ТехноРебут».
3. Обратите внимание на строку диагностики:
   - Отображается строка: **«Фото найдено: X из N»**.
   - Если прокрутить страницу вниз, все превью карточек подгружаются, и число найденных фото соответствует количеству карточек.

### Шаг 4: Пакетный импорт и проверка миниатюр в таблице инвентаря
1. В попапе расширения нажмите кнопку **«Импортировать все страницы»** (или «Импортировать текущую страницу»).
2. Дождитесь завершения импорта (появится сообщение об успешном импорте/обновлении).
3. Откройте в браузере страницу инвентаря ТехноРебут:  
   `https://localhost:8443/inventory/products`
4. **Проверьте таблицу товаров:**
   - В колонке **«Фото»** у каждого импортированного товара отображается аккуратная квадратная миниатюра (42x42 px).
   - При клике на миниатюру открывается полная карточка товара.
   - Внутри карточки товара отображается главное фото товара.
5. **Проверьте корректность цены:**
   - Для товаров с модельными номерами в названии (например, HP LaserJet P2055) цена сохранена корректно (например, 3 500 ₽, а не 2055 ₽).
6. **Проверьте повторный импорт:**
   - Нажмите импорт еще раз в расширении — дубликаты товаров и дубликаты фото **не создаются**.
