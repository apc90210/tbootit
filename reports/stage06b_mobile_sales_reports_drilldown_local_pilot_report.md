## 2. Иерархия Drill-down и Архитектурные Решения

### Принцип единого уровня детализации (Zero Accordion Invariant)
В соответствии с требованиями ТЗ исключены любые выпадающие («гармошки», аккордеоны, inline-expanders) списки внутри списков. Каждый экран отображает ровно один уровень детализации:
1. **Сегодня (`TODAY`)**:
   - Карточка сводки за сегодня (выручка, чеки, средний чек, наличные / карта / перевод).
   - Непосредственный плоский список чеков за сегодня (`ReceiptCard`).
   - Клик по чеку открывает отдельный экран чека (`ReceiptDetailScreen`).
2. **Неделя (`WEEK`)**:
   - Карточка сводки за текущую неделю.
   - Список дней недели с продажами (`DaySummaryCard`), отсортированный от новых к старым (каждый элемент: дата, день недели, количество чеков с правильным склонением, сумма, разбивка по типам оплат).
   - Клик по дню открывает отдельный экран дня (`DayReceiptsScreen`).
   - Клик по чеку дня открывает `ReceiptDetailScreen`.
3. **Месяц (`MONTH`) — СТРОГО без промежуточного уровня недель**:
   - Карточка сводки за текущий месяц.
   - **Напрямую список дней месяца** с продажами (`DaySummaryCard`), без группировки по неделям.
   - Клик по дню открывает экран дня (`DayReceiptsScreen`).
   - Клик по чеку открывает экран чека (`ReceiptDetailScreen`).
4. **Год (`YEAR`)**:
   - Карточка сводки за текущий год.
   - Список месяцев года с продажами (`MonthSummaryCard`), отсортированный от новых к старым.
   - Клик по месяцу открывает отдельный экран месяца (`MonthDaysScreen`) со списком дней месяца.
   - Клик по дню месяца открывает экран дня (`DayReceiptsScreen`) со списком чеков.
   - Клик по чеку открывает экран чека (`ReceiptDetailScreen`).

### Строгая симметрия навигации Назад (TopAppBar + System Back)
- В `MobileApp.kt` реализовано централизованное управление стеком родительских экранов:
  - `monthDaysParentScreen` (возврат в `MAIN` с сохранением вкладки `YEAR`).
  - `dayReceiptsParentScreen` (возврат либо в `MAIN` при вызове из Недели/Месяца, либо в `REPORT_MONTH_DAYS` при вызове из Года -> Месяца).
  - `receiptDetailParentScreen` (возврат либо в `REPORT_DAY_RECEIPTS`, либо в `MAIN`, либо в `POS_TERMINAL`).
- Локальное кэширование загруженных отчетов дня (`dayReceiptsCache`) и месяца (`monthDaysCache`) гарантирует мгновенный возврат назад без мерцания, лишних запросов и с сохранением позиции скролла.
- Нажатие на аппаратную кнопку / жест «Назад» Android (`BackHandler`) и нажатие на стрелку «Назад» в `TopAppBar` отрабатывают **абсолютно идентично**.

## 3. Бэкенд-изменения (`admin-shell`)

### 1. Расширение фасада `/api/mobile/reports/sales`
- Поддержка параметров фильтрации дат `date_from` и `date_to` (формат `YYYY-MM-DD`).
- Поддержка периода `period="custom"` для точной выборки чеков конкретного дня (`date_from == date_to`) или произвольного диапазона с сохранением валидации.
- Серверная математическая агрегация структур `days` и `months`:
  - `days`: агрегация по датам чеков (`payment_date`), расчет количества чеков, выручки, наличных/карты/перевода, локализованное наименование дня недели на русском языке (`Понедельник`, `Вторник`, ...).
  - `months`: агрегация по месяцам (`YYYY-MM`), расчет количества чеков, выручки, типов оплат, локализованное наименование месяца на русском языке (`Октябрь 2026`, ...).
  - Сохранение 100% математической сходимости: сумма оплат по дням/месяцам в точности совпадает с суммой родительского отчета.
- Строгая защита криптографической подписью **TRMOBILE1 PoP**:
  - `GET /api/mobile/reports/sales` требует действующий PoP-заголовок `X-Mobile-Signature` с валидацией таймстемпа (replay window 300s) и канонической строки запроса.

### 2. Интеграционные тесты бэкенда (`admin-shell/tests/test_stage06b_mobile_sales_reports_drilldown.py`)
Разработан специализированный набор тестов (8 сценариев):
1. `test_01_pop_auth_enforced_on_reports_sales`: Проверка обязательности PoP-аутентификации (401 без подписи).
2. `test_02_today_report_structure`: Валидация структуры отчета за сегодня (receipts, totals).
3. `test_03_week_report_aggregates_days`: Валидация дней недели и сходимости сумм.
4. `test_04_month_report_aggregates_days_directly`: Валидация прямого списка дней месяца без промежуточных недель.
5. `test_05_year_report_aggregates_months`: Валидация списка месяцев в годовом отчете.
6. `test_06_day_drilldown_custom_period`: Валидация выборки за конкретный день через `period="custom"`.
7. `test_07_invalid_date_format_rejected`: Проверка отклонения некорректных дат (422/400).
8. `test_08_empty_period_returns_zero_summary`: Проверка корректности нулевого ответа при отсутствии продаж за дату.

**Результат прогона тестов**: **8/8 PASSED** (3.56 с).

## 4. Клиентские изменения Android (`android-app`)

### 1. Модели данных (`SalesReport.kt`)
- Добавлены структуры:
  - `DayReportSummary(date, dayOfWeekName, receiptCount, totalRevenue, cashAmount, cardAmount, transferAmount)`
  - `MonthReportSummary(yearMonth, monthName, receiptCount, totalRevenue, cashAmount, cardAmount, transferAmount)`
- В `Period` добавлен вариант `CUSTOM("custom", "За период")`.
- В `SalesReport` добавлены поля `days: List<DayReportSummary>` и `months: List<MonthReportSummary>`.

### 2. Форматирование текста (`ReportFormatters.kt`)
- Функция `formatReceiptCount(count: Int)`: реализовано строгое склонение русских существительных (1 чек, 2 чека, 5 чеков, 21 чек, 24 чека и т.д.).
- Поддержка отображения периода `CUSTOM`.

### 3. Сетевой клиент (`MobileApiClient.kt`)
- Метод `getSalesReport(period, dateFrom, dateTo)`:
  - Каноническая лексикографическая сортировка query-параметров (`RequestBinding.canonicalizePath`) для формирования валидной подписи TRMOBILE1 PoP.

### 4. Пользовательский интерфейс (Jetpack Compose)
- **`DayReceiptsScreen.kt`**:
  - Карточка сводки дня: дата, количество чеков, выручка, бейджи оплаты (Наличные, Карта, Перевод).
  - Список чеков дня: `ReceiptCard` с номером чека, временем, суммой, типом оплаты.
  - Нажатие на чек открывает `ReceiptDetailScreen`.
  - Кнопка Назад в `TopAppBar` с поддержкой обратного перехода в родительский экран.
- **`MonthDaysScreen.kt`**:
  - Карточка сводки месяца: наименование месяца, количество чеков, выручка, бейджи типов оплат.
  - Список дней месяца: карточки `DaySummaryCard` (дата, день недели, чеки, сумма, типы оплат).
  - Нажатие на день открывает `DayReceiptsScreen` для выбранного дня.
  - Кнопка Назад в `TopAppBar` с возвратом к годовому отчету.
- **`SalesReportScreen.kt`**:
  - Вкладка «Сегодня»: сводка + плоский список чеков.
  - Вкладка «Неделя»: сводка + карточки дней `DaySummaryCard`.
  - Вкладка «Месяц»: сводка + **прямой список карточек дней `DaySummaryCard`** (без аккордеонов).
  - Вкладка «Год»: сводка + карточки месяцев `MonthSummaryCard`.
- **`MobileApp.kt`**:
  - Маршруты `AppScreen.REPORT_MONTH_DAYS` и `AppScreen.REPORT_DAY_RECEIPTS`.
  - Сохранение состояния родительских экранов и кэшей данных.
  - Полная поддержка аппаратного и экранного «Назад».
