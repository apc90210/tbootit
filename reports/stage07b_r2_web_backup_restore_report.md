## 1. Контекст и выполненные требования

Владелец системы категорически отклонил подход с использованием CMD-скриптов и ручных терминальных команд (Stage 07B-R1). Все операции обслуживания системы должны производиться на 100% онлайн через браузер в защищенной панели управления `admin-shell`.

### Реализовано:
1. **Удалены устаревшие CMD-скрипты:**
   - Удалены `backup/backup_full.cmd` и `backup/restore_full.cmd`.
   - Обновлен `backup/README.md` с удалением любых упоминаний командной строки и документированием исключительно веб-сценария.
2. **Веб-интерфейс Владельца (`/backups`):**
   - Добавлен пункт навигации **«Резервные копии»** во все шаблоны (`index.html`, `certificates.html`, `backups.html`).
   - Разработана веб-страница управления бэкапами в едином фирменном неоново-темном стиле (Cyberpunk Glow / Dark UI).
   - Секция создания резервной копии с кнопкой `[ Скачать резервную копию ]`, индикатором процесса и автоматической передачей файла `TECHNOREBOOT_BACKUP_YYYY-MM-DD_HHMMSS.zip` в загрузки браузера.
   - Секция восстановления с выбором файла, предупреждением о перезаписи, диалоговым подтверждением, индикатором прогресса и детальным статусом выполнения.
3. **Безопасность и разграничение доступа (mTLS OWNER only):**
   - Доступ к `/backups`, `/admin-api/backups/download` и `/admin-api/backups/restore` строго ограничен сертификатом Владельца (`_require_owner`).
   - Обычные пользователи (USER) и неаутентифицированные клиенты получают `403 Forbidden`.
4. **Сервис создания архива (`admin-shell/app/backup_service.py`):**
   - Транзакционный снимок SQLite базы через `sqlite3.Connection.backup()`.
   - Полный текстовый SQL-дамп всех таблиц (`.iterdump()`).
   - Фотографии товаров из `storage/product_photos/`.
   - Полная PKI-инфраструктура mTLS (`ca/`, `certificates/`, `registry.json`, `owner_password.txt`).
   - Структурированный манифест `manifest.json` со статистикой БД и отпечатками сертификатов.
   - Полное исключение исходного кода (`.py`), репозитория Git (`.git/`) и Docker-образов.
   - Потоковая отдача файла и фоновая очистка временных файлов на сервере.
5. **Сервис валидации и восстановления (`restore_backup`):**
   - Предварительная проверка ZIP-архива (`testzip()`), манифеста и критических файлов до внесения каких-либо изменений на сервере.
   - Защита точек монтирования Docker (сохранение корневых дескрипторов каталогов `data/`).
   - Атомарное обновление БД и медиа-хранилища.
   - Пост-верификация целостности базы и неизменности отпечатков CA и сертификата Владельца.
   - Немедленная доступность новых данных без необходимости перезапуска стека или повторного входа.

## 4. Пошаговый сценарий ручной проверки для Владельца (Web UI Only)

1. Откройте браузер Chrome, Edge или Firefox.
2. Перейдите по адресу: `https://localhost:8443`
3. Выберите сертификат Владельца (`Technoreboot OWNER`).
4. В верхней навигационной панели нажмите кнопку **«Резервные копии»** (синяя кнопка рядом с «Доступ (mTLS)»).
5. Нажмите **«Скачать резервную копию»**:
   - В браузере начнется скачивание файла `TECHNOREBOOT_BACKUP_... .zip`.
6. Для проверки восстановления:
   - В секции «Восстановление» нажмите «Выберите файл» и укажите скачанный архив.
   - Нажмите «Восстановить систему» и подтвердите действие.
   - Появится зеленая плашка с подтверждением успешного восстановления.
   - Перейдите в раздел «Товары» или «Доступ» — система мгновенно готова к работе.
