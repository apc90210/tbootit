## 1. Резюме проблемы и первопричин (Root Cause Analysis)

В ходе реального тестирования в браузере при пакетном импорте объявлений из профиля продавца Авито (`/profile/items`) возникали три критические взаимосвязанные проблемы:

### 1.1. Первопричина HTTP 422 `missing body`
1. В `popup.js` при отправке пакета объявлений в фоновый сервис-воркер вызывался метод:
   ```javascript
   chrome.runtime.sendMessage({ action: "bulk_import_batch", items: batchItems }, ...);
   ```
   где данные передавались под ключом `items`, а ключ `payload` отсутствовал.
2. В `service_worker.js` обработчик сообщения ожидал `request.payload`:
   ```javascript
   const payload = request.payload; // === undefined!
   ```
3. При формировании HTTP POST запроса в `sendBulkImportPayload`:
   ```javascript
   body: JSON.stringify(payload) // JSON.stringify(undefined) === undefined
   ```
   Метод `fetch` с `body: undefined` отправлял HTTP POST запрос с **абсолютно пустым телом** на эндпоинт `/admin-api/avito-extension/bulk-import`.
4. Бэкенд FastAPI (Pydantic v2), ожидая модель `BulkImportPayload`, возвращал ошибку валидации:
   ```json
   HTTP 422 Unprocessable Entity
   [{"type":"missing","loc":["body"],"msg":"Field required","input":null,"url":"https://errors.pydantic.dev/2.5/v/missing"}]
   ```
5. Сервис-воркер преобразовывал этот JSON в строку и возвращал в popup, в результате чего пользователю демонстрировалось сырое техническое сообщение с утечкой ссылок на документацию Pydantic (`https://errors.pydantic.dev/...`).

### 1.2. Ложный зеленый статус («Импорт успешно завершен») и поломка баланса учета
- В `popup.js` счетчик `totalProcessed` инкрементировался на длину отправленного пакета (`batchItems.length`) **до или независимо** от ответа сервера.
- При получении ошибки HTTP 422 сервер не сохранял ни одного объявления (0 создано, 0 обновлено).
- Тем не менее цикл импорта завершался, и в блоке `finally` выводился зеленый баннер успеха:
  ```text
  ✓ Импорт успешно завершен!
  Страниц обработано: 1, объявлений: 50
  ```
- В системе образовался разрыв: в UI отображался 100% успех, а в базе данных Техноребут товары отсутствовали.

### 1.3. Расхождение между импортом текущей страницы и всех страниц
- Кнопка «Импортировать текущую страницу» и «Импортировать все объявления» содержали дублирующийся, нескоординированный код сборки пакетов, из-за чего логика исправления могла работать для одного режима и ломать другой.

### 1.4. Сброс состояния при постраничной навигации
- При переходе между страницами профиля на Авито (SPA или полный reload) контекст всплывающего окна мог перезагружаться, теряя уже просмотренные `seenAvitoIds`, текущий номер страницы и промежуточную статистику.

## 2. Реализованное техническое решение

### 2.1. Единый канонический отправитель пакетов (`sendBulkBatch`)
В `chrome-extension/technoreboot-avito/popup.js` внедрена единая вспомогательная функция `sendBulkBatch(batchItems)`:
- Проверяет непустоту массива объявлений.
- Нормализует структуру отправляемых данных.
- Передает в фоновый скрипт гарантированно согласованный объект:
  ```javascript
  chrome.runtime.sendMessage({
    action: "bulk_import_batch",
    payload: {
      schema_version: 1,
      extension_version: manifestVer,
      captured_at: new Date().toISOString(),
      page_type: "bulk_import",
      items: batchItems
    },
    items: batchItems
  });
  ```
- Единообразно обновляет счетчики `totalCreated`, `totalUpdated`, `totalSkipped`, либо регистрирует ошибки в массив `allErrors`.
- Обе кнопки — `bulkImportCurrentBtn` и `bulkImportAllBtn` — используют исключительно эту функцию.

### 2.2. Двусторонняя защита от отсутствия тела запроса
1. **На клиенте (`service_worker.js`)**:
   - Обработчик сообщения принимает как `request.payload`, так и альтернативный `request.items`.
   - Если передан плоский массив `items` или обернутый словарь, функция `sendBulkImportPayload` нормализует его к строгой схеме с полями `schema_version: 1`, `extension_version: "0.2.50"`, `captured_at`, `page_type: "bulk_import"`, `items`.
   - Проверяется сериализованная строка `bodyJson`: если она пуста или равна `"undefined"`, отправка прерывается с локальной понятной ошибкой до выполнения сетевого запроса.
2. **На сервере (`avito-module/app/routers/extension_bridge.py`)**:
   - Эндпоинт `receive_bulk_import` типизирован как `Union[BulkImportPayload, List[Dict[str, Any]]]`.
   - Если клиент присылает сырой JSON-массив объявлений, бэкенд автоматически конвертирует его в каноническую модель `BulkImportPayload` со значениями по умолчанию, предотвращая возникновение 422 ошибки.

### 2.3. Строгий инвариант баланса учета и политика финального статуса
- **Инвариант:**
  $$\text{totalCreated} + \text{totalUpdated} + \text{totalSkipped} + \text{allErrors.length} \equiv \text{число переданных объявлений}$$
- **Политика отображения статуса:**
  - Зеленый статус `msg msg-success` («✓ Импорт успешно завершен») выводится **только и исключительно тогда**, когда:
    `allErrors.length === 0 && (totalCreated + totalUpdated + totalSkipped) > 0`.
  - Если в процессе возникла хотя бы одна ошибка (`allErrors.length > 0`), статус окрашивается в цвет предупреждения или ошибки (`msg-warning` / `msg-error`) с указанием точного количества неудачных позиций и текстом: «Импорт завершен с ошибками».
  - Если обработано 0 объявлений (или ничего не создано и не обновлено при наличии ошибок), зеленый статус категорически запрещен.

### 2.4. Санитизация технических ошибок и русификация
- В `service_worker.js`:
  - Функция `parseJsonResponseSafely` при получении HTTP 422 с ошибкой `missing body` формирует понятное пользователю сообщение:
    *«Ошибка отправки данных в Техноребут: сервер не получил пакет объявлений.»*
  - Регулярным выражением `https?://errors\.pydantic\.dev[^\s"']*` гарантированно удаляются любые внутренние ссылки на документацию Pydantic.
- В `popup.js`:
  - Функция `sanitizeErrorMessage` переводит сетевые ошибки `Failed to fetch`, CORS, `Load failed` и серверные сбои в чистые русскоязычные сообщения без сырых стектрейсов.

### 2.5. Сохранение сессии постраничного импорта (`chrome.storage.session`)
- При запуске многостраничного импорта текущее состояние сохраняется в хранилище сессии браузера:
  - `key: bulk_import_session`
  - Поля: `in_progress`, `currentPage`, `maxPages`, `seenAvitoIds`, `visitedUrls`, `totalCreated`, `totalUpdated`, `totalSkipped`, `allErrors`.
- При переходе по ссылкам пагинации и кликах на следующую страницу content script выполняет до 3 попыток асинхронного извлечения с ожиданием гидратации SPA React (до 10 секунд).
- Сессия автоматически очищается после завершения либо явной отмены пользователем.

## 4. Пошаговая инструкция для Владельца (Проверка в браузере)

Проверка выполняется **исключительно в браузере** (без использования CLI и сторонних скриптов):

1. **Скачивание и установка расширения v0.2.50:**
   - Откройте в браузере с установленным клиентским сертификатом страницу:
     `https://localhost:8443/avito/extension`
   - Убедитесь, что в заголовке указана версия **0.2.50**.
   - Нажмите кнопку «Скачать расширение (ZIP)» (файл `technoreboot-avito-extension-0.2.50.zip`).
   - Распакуйте архив в удобную папку на компьютере.
   - В Google Chrome / Chromium откройте страницу `chrome://extensions`.
   - Включите «Режим разработчика» (в правом верхнем углу).
   - Если была установлена предыдущая версия (0.2.49 или 0.2.48) — удалите её или нажмите «Обновить».
   - Нажмите «Загрузить распакованное расширение» и выберите папку с версией 0.2.50.
   - Убедитесь, что версия расширения в списке расширений — **0.2.50**.

2. **Проверка сопряжения:**
   - Откройте всплывающее окно плагина (клик на иконку Техноребут в панели расширений).
   - В окне плагина должна отображаться версия **v0.2.50**.
   - Если статус «Не сопряжено»:
     - На странице `https://localhost:8443/avito/extension` нажмите «Сгенерировать код сопряжения».
     - Введите полученный 6-значный код в окне расширения и нажмите «Сопрячь».
     - Статус должен смениться на зеленый: «✓ Сопряжено с сервером Техноребут».

3. **Проверка импорта текущей страницы личного кабинета Авито:**
   - Перейдите на вкладку личного кабинета Авито: `https://www.avito.ru/profile/items` (или страницу ваших активных объявлений).
   - Откройте всплывающее окно расширения.
   - Убедитесь, что плагин определяет тип страницы как «Список объявлений (кабинет / профиль)» и показывает ненулевое количество найденных объявлений (например, «Найдено объявлений на странице: 25»).
   - Нажмите кнопку **«Импортировать текущую страницу»**.
   - Наблюдайте за процессом:
     - Ошибки `HTTP 422: missing body` больше **не возникает**.
     - Прогресс-бар корректно заполняется.
     - По завершении выводится сообщение:
       *«✓ Импорт успешно завершен! Создано: N, обновлено: M.»*
     - Баланс учета строго сходится: создано + обновлено = общее число объявлений на странице.

4. **Проверка многостраничного импорта (при наличии пагинации):**
   - Нажмите **«Импортировать все объявления»**.
   - Плагин выполнит последовательный импорт страницы 1, перейдет к следующей странице, сохранив сессию в `chrome.storage.session`, извлечет объявления и отправит следующий пакет.
   - При завершении выводится итоговый отчет с суммарным количеством созданных и обновленных карточек.

5. **Проверка импортированных товаров в системе:**
   - Откройте в браузере: `https://localhost:8443/inventory/products`.
   - Убедитесь, что импортированные объявления появились в списке товаров Техноребут со статусом `DRAFT`, ценой, заголовком и ссылкой на объявление на Авито.
