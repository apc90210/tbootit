# TR — Product Search + OWNER Delete — R1

Работаем с проектом «Техноребут» / tbootit.

Нужно локально исправить две небольшие проблемы в модуле товаров.

## 1. Поиск товаров без учёта регистра

Сейчас поиск различает большие и маленькие буквы.

Нужно сделать регистронезависимый поиск для кириллицы и латиницы:
- `монитор`
- `Монитор`
- `МОНИТОР`
- `мОнИтОр`

должны давать одинаковый результат.

Не полагаться только на стандартный SQLite `COLLATE NOCASE`, если это не обеспечивает корректную работу с кириллицей. Реализовать минимальное надёжное Unicode-aware решение в рамках текущей архитектуры.

Проверить все поля, по которым сейчас выполняется поиск товаров.

## 2. Удаление ошибочного товара OWNER

OWNER, авторизованный OWNER-сертификатом, должен иметь простой способ удалить ошибочный товар из интерфейса.

Требования:
- действие доступно только OWNER;
- backend также обязан проверять права, одной скрытой кнопки недостаточно;
- перед удалением должно быть подтверждение;
- новый товар без исторических связей можно удалить;
- если товар связан с продажами, ремонтами или другой значимой историей — нельзя ломать историю или FK. Использовать существующее безопасное поведение (архив/soft-delete/запрет) либо реализовать минимально безопасный вариант;
- зафиксировать действие в существующем audit log;
- после успешного действия список товаров должен корректно обновиться.

## Ограничения

- Работать только LOCAL/dev.
- Production/VDS не трогать.
- Не делать широкий рефакторинг.
- Не удалять реальные данные.
- Не ломать продажи, ремонты, остатки, Avito и media.

## Проверка

После реализации проверить:
- поиск на кириллице и латинице в разном регистре;
- OWNER может удалить тестовый товар без связей;
- USER удалить товар не может;
- товар с историческими связями не повреждает историю;
- `PRAGMA foreign_key_check` — чисто;
- `PRAGMA quick_check` — `ok`.
