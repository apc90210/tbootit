# TR — Product Search + OWNER Delete — R4 Trust Boundary

R3 в целом принят. Нужна последняя точечная проверка безопасности перед OWNER manual test.

## Цель

Подтвердить, что `x-auth-is-owner: 1` нельзя подделать обычным клиентским запросом.

Сейчас Core разрешает удаление при точном значении:

`x-auth-is-owner: 1`

Это допустимо только если данный заголовок формируется доверенным mTLS/admin-shell слоем и внешний клиент не может самостоятельно передать его в Core.

## Проверить

1. Как фактически проходит запрос:
   OWNER certificate -> nginx/admin-shell -> inventory/core.

2. Доступен ли Core API напрямую:
   - с локальной сети;
   - извне/VDS;
   - через опубликованный nginx route.

3. Может ли обычный USER или запрос без OWNER-сертификата отправить:
   `x-auth-is-owner: 1`
   и получить OWNER-доступ.

4. На доверенном прокси проверить:
   - входящий от клиента `x-auth-is-owner` должен игнорироваться/удаляться;
   - прокси должен сам выставлять owner-признак только после успешной проверки OWNER certificate.

5. Проверить аналогично оба пути удаления:
   - inventory UI/API;
   - admin-shell/API.

## Если spoofing возможен

Исправить минимально в рамках существующей mTLS архитектуры:
- не вводить новую auth-систему;
- удалить/перезаписать пользовательский `x-auth-is-owner` на доверенной границе;
- Core должен получать owner-признак только от доверенного внутреннего слоя.

Добавить regression test на попытку spoofing.

## После проверки

Верни короткий отчёт:

1. Trust boundary — PASS/FAIL.
2. Кто именно создаёт `x-auth-is-owner`.
3. Можно ли клиенту подделать его.
4. Какие ingress/proxy routes ведут к Core.
5. Что было изменено, если потребовалось.
6. Результаты тестов.
7. `git status` и список незакоммиченных файлов.
