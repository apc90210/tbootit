# TR — Product Search + OWNER Delete — R3 Audit

R2 пока не принимать. Нужен контрольный аудит фактического кода и тестов БЕЗ новых архитектурных изменений.

Проверь и дай точный ответ по текущему состоянию репозитория.

## 1. OWNER authorization

Подтверди фактическими тестами:

- заголовок OWNER отсутствует -> 403;
- `x-auth-is-owner: 0` -> 403;
- некорректное значение -> 403;
- только подтвержденный OWNER -> удаление разрешено.

Покажи, где именно в коде выполняется fail-closed проверка.

Важно: отсутствие заголовка не должно трактоваться как OWNER.

## 2. Исторические связи

Проверь, что hard delete НЕ удаляет и НЕ подчищает исторические данные.

Отдельно проверить товары, у которых существуют:

- `sale_items`;
- `stock_movements`;
- `product_events`;
- `repair_parts` или иные связи с ремонтами;
- `avito_post_sale_tasks` / исторические Avito-связи;
- любые другие FK на `products`.

Для каждой связи укажи:
- считается ли она исторической;
- hard delete запрещён или нет;
- что происходит вместо него.

Особенно проверить `product_events`: в R1 они удалялись при hard delete. Это больше недопустимо.

## 3. Soft delete

Уточни ФАКТИЧЕСКУЮ реализацию.

Не описывай предположительно.

Укажи:
- используется `is_archived`,
- или `status="archived"`,
- или другой механизм.

Покажи точные поля модели Product и логику скрытия архивного товара из обычного каталога/поиска.

## 4. Audit log

Подтверди, что:
- hard delete записывается в существующий `audit_log`;
- soft delete / archive записывается в `audit_log`;
- запись содержит product id и тип операции.

Если этого нет — исправить минимально и добавить тест.

## 5. Database integrity

Обязательно выполнить:

`PRAGMA foreign_key_check`
`PRAGMA quick_check`

Ожидается:
- foreign_key_check -> пусто;
- quick_check -> `ok`.

## 6. Regression

Повторно запустить:
- тесты поиска кириллицы/латиницы;
- тесты OWNER deletion;
- тесты Stage11D owner bulk delete;
- hard delete audit tests;
- product safety tests.

## 7. Итоговый отчёт

Верни КОРОТКИЙ отчёт:

1. PASS/FAIL по каждому пункту R3.
2. Точная реализация OWNER fail-closed.
3. Полный список исторических связей, блокирующих hard delete.
4. Точный механизм soft delete.
5. Audit log — PASS/FAIL.
6. Результаты всех тестов.
7. `foreign_key_check`.
8. `quick_check`.
9. Какие файлы пришлось изменить, если изменения понадобились.

Production/VDS не трогать.
После отчёта остановиться.
