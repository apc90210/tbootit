# Спецификация и архитектура: Stage 07C-R1-R1 — Выборочный экспорт товаров в JSON и верификация доступа Владельца

## 1. Назначение и контекст

Этап **Stage 07C-R1-R1** расширяет функционал канонического экспорта товаров в JSON (`/products/json`), предоставляя Владельцу и операторам возможность интерактивного выбора **одного или нескольких конкретных товаров** для выгрузки, сохраняя при этом кнопку выгрузки всей базы («Экспортировать все товары»).

Также в рамках данного этапа проведена строгая верификация и стандартизация матрицы доступа Gateway mTLS для страницы `/products/json` и сопутствующих API.

### 2.1. Контракт выборочного экспорта (Core API)

1. **Эндпоинт GET `/api/products/json/export`**:
   - Query параметр: `ids` (строка с разделителями-запятыми, например `?ids=1,5,10` или повторяющийся параметр `?ids=1&ids=5`).
   - Если параметр `ids` опущен или пуст — экспортируются все товары каталога.
   - Если передан список `ids` — возвращается канонический JSON, содержащий **только** указанные товары в порядке переданных ID.
   - Если какие-то ID отсутствуют в БД, они безопасно пропускаются без генерации исключений (500).

2. **Эндпоинт POST `/api/products/json/export`** (и алиас `POST /api/products/cards/export-canonical-json`):
   - Request Body: `{"ids": [1, 5, 10]}`.
   - Предотвращает ограничения веб-серверов на длину URL при выгрузке сотен выбранных позиций.
   - Ответ: `200 OK`, `Content-Type: application/json; charset=utf-8`.

3. **Admin Shell Proxy (`/admin-api/products/json/export`)**:
   - Поддерживает методы `GET` (с query-параметром `ids`) и `POST` (с телом `{"ids": [...]}`).
   - Пересылает запрос в Core API и возвращает файл клиенту с заголовком `Content-Disposition: attachment; filename="TECHNOREBOOT_PRODUCTS_YYYY-MM-DD_HHMMSS.json"`.

## 3. Сравнение контрактов: Одиночный, Множественный и Полный экспорт

Все виды экспорта формируют **абсолютно идентичную каноническую структуру данных** схемы `technoreboot-products` версии 1:

| Характеристика | Одиночный экспорт (1 товар) | Множественный экспорт (N товаров) | Полный экспорт (все товары) |
| :--- | :--- | :--- | :--- |
| **Формат (`format`)** | `"technoreboot-products"` | `"technoreboot-products"` | `"technoreboot-products"` |
| **Версия (`version`)** | `1` | `1` | `1` |
| **Массив `products`** | Содержит ровно 1 объект | Содержит ровно N объектов | Содержит все товары каталога |
| **Порядок товаров** | Соответствует запрошенному ID | Соответствует переданному порядку `ids` | Упорядочен по ID / дате создания |
| **Характеристики** | Полный словарь `characteristics` | Полный словарь `characteristics` | Полный словарь `characteristics` |
| **Фотографии** | Полный массив `photos` (безопасный `media_url`/`source_url`/`storage_path`) | Полный массив `photos` | Полный массив `photos` |
| **Имя скачиваемого файла** | `TECHNOREBOOT_PRODUCTS_YYYY-MM-DD_HHMMSS.json` | `TECHNOREBOOT_PRODUCTS_YYYY-MM-DD_HHMMSS.json` | `TECHNOREBOOT_PRODUCTS_YYYY-MM-DD_HHMMSS.json` |
| **Совместимость с Импортом** | 100% валиден для повторного импорта | 100% валиден для повторного импорта | 100% валиден для повторного импорта |

## 4. Матрица контроля доступа (mTLS Gateway)

Все внешние запросы к панели управления проходят через защищенный Nginx Gateway (`https://<host>:8443`) с обязательной проверкой клиентского TLS-сертификата (`ssl_verify_client optional` с валидацией через `auth_manager`).

| Сертификат / Клиент | Доступ к `/products/json` (Web UI) | Экспорт / Импорт JSON | Обоснование политики |
| :--- | :---: | :---: | :--- |
| **Без клиентского сертификата** | **403 Forbidden** | **403 Forbidden** | Любые неаутентифицированные запросы с внешнего интерфейса блокируются Gateway. |
| **Сертификат Владельца (Owner)** | **200 OK** | **200 OK** | Владелец обладает абсолютными правами доступа ко всем разделам системы, включая системные (сертификаты, бэкапы). |
| **Сертификат Пользователя (User)** | **200 OK** | **200 OK** | Активный оператор/пользователь имеет штатный доступ к управлению товарами каталога (`/inventory/products`, `/products/json`), но не имеет доступа к системным разделам Владельца (`/certificates`, `/backups`). |
| **Отозванный / Неактивный сертификат** | **403 Forbidden** | **403 Forbidden** | Блокируется модулем авторизации при проверке отпечатка (`thumbprint`). |

## 5. Описание пользовательского интерфейса (Web UI Workflow)

Страница `/products/json` в Секции C («Экспорт товаров в JSON») содержит:

1. **Интерактивный поисковый фильтр:**
   - Поле `[ 🔍 Поиск / фильтр товаров... ]` фильтрует список на лету по артикулу (SKU), названию, бренду, модели или ID.
   - Фильтрация скрывает нерелевантные строки, но сохраняет состояние уже установленных чекбоксов.

2. **Кнопки группового управления выбором:**
   - `[ ✓ Выбрать все показанные ]`: отмечает чекбоксы только тех товаров, которые видны в текущем отфильтрованном представлении.
   - `[ ✕ Снять выбор ]`: полностью очищает выбор со всех товаров каталога.

3. **Интерактивный список товаров с чекбоксами:**
   - Компактный скроллируемый список (`max-height: 380px`).
   - Каждая строка содержит: чекбокс с `data-id`, бейдж с ID (`#105`), SKU товара, жирное название, бренд и цену.
   - Клик по всей строке переключает чекбокс.
   - Выбранные строки подсвечиваются мягким синим фоном.

4. **Живой счетчик выбранных товаров:**
   - Строка статуса: `Выбрано для экспорта: N` (где N динамически обновляется при каждом клике).

5. **Контролируемая валидация нулевого выбора:**
   - Если пользователь нажимает кнопку `[ 📦 Экспортировать выбранные в JSON ]`, когда `N == 0`:
     - Сетевой запрос **НЕ отправляется**.
     - Показывается четкое русскоязычное предупреждение в янтарной плашке:
       `Выберите хотя бы один товар для экспорта.`
     - Фокус автоматически переводится на поле поиска товаров.

6. **Кнопки выгрузки:**
   - `[ 📦 Экспортировать выбранные в JSON ]`: выгружает файл только с отмеченными позициями.
   - `[ 🌐 Экспортировать все товары в JSON ]`: выгружает полный каталог (143+ товаров).

## 6. Руководство по устранению неполадок: Ошибка 403 на `/products/json`

Если Владелец или пользователь сталкивается с ошибкой `403 Forbidden` при обращении к `https://127.0.0.1:8443/products/json`:

1. **Проверка наличия сертификата в браузере:**
   - Браузер должен иметь установленный персональный сертификат Владельца (`.p12` / `.pfx`), выпущенный корневым удостоверяющим центром системы (`technoreboot-ca.crt`).
   - В Windows: `certmgr.msc` -> «Личное» (Personal) -> «Сертификаты». Убедитесь, что сертификат Владельца присутствует и действителен.
   - В Google Chrome / Edge: `Настройки -> Конфиденциальность и безопасность -> Безопасность -> Управление сертификатами устройств -> Личные`.

2. **Очистка кэшированной SSL-сессии:**
   - Если браузер запомнил выбор «Без сертификата» или использовал недействительный сеанс, перезапустите браузер либо откройте окно в режиме инкогнито и при запросе выберите сертификат Владельца.
   - В Windows: `Свойства браузера (inetcpl.cpl) -> Содержание -> Очистить SSL`.

3. **Проверка совпадения отпечатка (Thumbprint):**
   - Убедитесь, что отпечаток сертификата зарегистрирован в реестре сертификатов `admin-shell` с ролью `OWNER` и статусом `ACTIVE`.
