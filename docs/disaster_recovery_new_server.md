# Инструкция по аварийному восстановлению ТехноРебут на новый сервер (Disaster Recovery Runbook)

> **Сценарий аварии:**
> Старый сервер безвозвратно недоступен или уничтожен.
> В наличии:
> 1. Чистый VDS/сервер с Debian 12 (или Ubuntu 22.04/24.04 LTS).
> 2. Доступ к Git-репозиторию проекта ТехноРебут.
> 3. Один актуальный архив резервной копии ТехноРебут (`TECHNOREBOOT_BACKUP_YYYY-MM-DD_HHMMSS.zip`).

---

## 1. Предварительные требования к новому серверу

На новом сервере должны быть установлены базовые системные пакеты:
- **Git**
- **Python 3** (версии 3.9+) и пакет `python3-cryptography`
- **Docker Engine** и плагин **Docker Compose v2**

### Быстрая установка зависимостей на чистом Debian 12 / Ubuntu:

```bash
# Обновление пакетов и установка базовых утилит
sudo apt-get update && sudo apt-get install -y git curl python3 python3-pip python3-cryptography unzip

# Установка Docker и Docker Compose (официальный скрипт Docker)
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
```

---

## 2. Клонирование репозитория

Склонируйте исходный код проекта на новый сервер (например, в директорию `/tbootit` или домашнюю папку):

```bash
git clone https://github.com/your-org/tbootit.git /tbootit
cd /tbootit
```

---

## 3. Размещение архива резервной копии

Скопируйте ваш архив резервной копии (`TECHNOREBOOT_BACKUP_*.zip`) на новый сервер в папку `backups/` внутри репозитория:

```bash
# Пример копирования через scp с вашего локального компьютера:
# scp C:\Users\Apc\Downloads\TECHNOREBOOT_BACKUP_2026-09-11_103952.zip user@new-server-ip:/tbootit/backups/

mkdir -p /tbootit/backups
mv /path/to/TECHNOREBOOT_BACKUP_*.zip /tbootit/backups/
```

Если архив находится в другом месте на сервере, вы можете передать прямой путь к нему аргументом в команду восстановления.

---

## 4. Запуск восстановления одной командой

Перейдите в корень репозитория и запустите скрипт аварийного восстановления:

```bash
cd /tbootit
chmod +x scripts/bootstrap_restore.sh
./scripts/bootstrap_restore.sh
```

*(Если архив лежит вне папки `backups/`, укажите путь к нему: `./scripts/bootstrap_restore.sh /path/to/archive.zip`)*

### Что делает скрипт автоматически:
1. **Проверяет окружение:** валидирует наличие Python, cryptography, Docker и структуры репозитория.
2. **Проверяет безопасность архива:** блокирует уязвимости Zip Slip (любые попытки выхода за пределы директории `../` или абсолютные пути).
3. **Валидирует манифест и компоненты:** удостоверяется, что в архиве есть база данных SQLite, медиафайлы и ключи/сертификаты PKI.
4. **Выполняет безопасную поэтапную распаковку:** сначала во временную директорию (staging), проверяет целостность SQLite базы данных (`PRAGMA integrity_check`) и сертификатов.
5. **Синхронизирует данные:** восстанавливает базу данных, фотографии товаров, Avito-состояние и корневой удостоверяющий центр (CA) с сертификатом Владельца.
6. **Выставляет права доступа:** защищает приватные ключи (`0600`) и сертификаты.
7. **Поднимает стек контейнеров:** запускает Docker Compose, ожидает готовности всех сервисов и шлюза mTLS.
8. **Проверяет целостность:** сверяет количество товаров, связей с Авито, продаж, наличие фото на диске и распознавание сертификата Владельца.

## 6. Как войти в восстановленную систему

Так как при восстановлении был сохранен исходный удостоверяющий центр (CA), **ранее выданный вам сертификат Владельца (`owner.p12`) остался действительным!** Вам **не нужно** перевыпускать сертификаты.

1. Откройте браузер, в котором установлен сертификат Владельца (`owner.p12`).
2. Перейдите по адресу нового сервера:
   ```text
   https://<NEW_SERVER_IP>:8443/
   ```
   *(Или `https://localhost:8443/`, если проверяете локально)*.
3. Браузер запросит выбор клиентского сертификата — выберите сертификат **OWNER**.
4. Проверьте ключевые разделы:
   - **Товары:** `https://<NEW_SERVER_IP>:8443/inventory/products` — отображаются товары с фотографиями.
   - **Отчёты:** `https://<NEW_SERVER_IP>:8443/reports/sales` — отображаются продажи и выручка.
   - **Ремонты:** `https://<NEW_SERVER_IP>:8443/repairs` — отображаются квитанции ремонтов.
   - **Расширение Авито:** `https://<NEW_SERVER_IP>:8443/avito/extension` — доступен архив и токен.
   - **Резервные копии:** `https://<NEW_SERVER_IP>:8443/backups` — доступен раздел управления бэкапами (только для Владельца).

---

## 7. Чего делать НЕЛЬЗЯ при аварийном восстановлении

- ❌ **НЕ генерируйте новый CA вручную** до восстановления — это сделает недействительными ранее выданные сертификаты Владельца и пользователей. Скрипт `bootstrap_restore.sh` автоматически восстановит действующий CA из бэкапа.
- ❌ **НЕ распаковывайте архив вручную в корень диска `root`** — архив содержит структуру путей для каталога `data/`.
- ❌ **НЕ переключайте публичный боевой DNS-домен** до того, как лично убедитесь в браузере, что система на новом сервере открывается по HTTPS и принимает сертификат Владельца.
