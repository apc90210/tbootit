# ТехноРебут — Документация mTLS (Stage 07A-R1)
## Минимальный доступ по сертификатам (Certificate-Based Access Control)

### 1. Назначение и концепция
В рамках этапа Stage 07A-R1 в систему «ТехноРебут» внедрён шлюз взаимной аутентификации TLS (mTLS). Он обеспечивает строгий контроль сетевого доступа к панели управления и API без использования внешних облачных провайдеров, парольных форм, OAuth или JWT:
- Доступ разрешён только клиентам, предъявившим валидный X.509 клиентский сертификат, подписанный локальным центром сертификации (CA).
- Без клиентского сертификата или при наличии недействительного сертификата шлюз возвращает `403 Forbidden` на уровне TLS.
- Предусмотрены две основные роли: **OWNER** (Владелец) и **USER** (Сотрудник / рабочее место).

---

### 2. Архитектура решения

1. **Входной шлюз (`technoreboot-gateway`)**:
   - Контейнер Nginx, принимающий входящие HTTPS-соединения на порту `8443` (и готовый к привязке на `443`).
   - Настройка `ssl_verify_client on;` требует обязательного предоставления клиентского сертификата.
   - Корневой сертификат `ca.crt` монтируется в шлюз в режиме read-only (`:ro`).
   - Каждый входящий запрос проверяется через директиву `auth_request /internal-auth/verify;`, направляемую во внутренний сервис `admin-shell`.
   - Шлюз очищает клиентские заголовки и транслирует в приложение верифицированные заголовки:
     - `X-Client-Verified`: статус валидации TLS (`SUCCESS`).
     - `X-Client-DN`: Distinguished Name субъекта.
     - `X-Client-Serial`: серийный номер сертификата в hex.
     - `X-Client-Fingerprint`: отпечаток SHA-256 сертификата.
     - `X-Client-Is-Owner`: признак владельца (`1` или `0`).
     - `X-Client-Cert-Name`: имя сертификата.

2. **Центр сертификации и реестр (`AuthManager` в `admin-shell`)**:
   - Реализован на стандартной библиотеке Python `cryptography`.
   - При первом запуске автоматически инициализирует:
     - Root CA (`data/auth/ca/ca.crt`, `data/auth/ca/ca.key`).
     - Сертификаты шлюза (`data/auth/certificates/server.crt`, `server.key`).
     - Сертификат и защищённый архив PKCS#12 (`data/auth/certificates/owner.p12`) для Владельца.
     - Случайный стойкий пароль владельца, сохраняемый в `data/auth/owner_password.txt`.
     - Реестр сертификатов (`data/auth/registry.json`).
   - Предоставляет внутренний эндпоинт `/internal-auth/verify` для валидации шлюзом.
   - Защита сертификата владельца: отзыв сертификата OWNER программно заблокирован на уровне ядра AuthManager (`Cannot revoke OWNER certificate`).

3. **Разграничение ролей**:
   - **OWNER**: Полный доступ ко всем модулям, включая веб-интерфейс управления сертификатами `/certificates` и API управления `/admin-api/certificates`.
   - **USER**: Доступ к операционным модулям (Товары, Продажи, Ремонты, Расширение Avito), запрет доступа к `/certificates` и `/admin-api/certificates` (`403 Forbidden`).

---

### 3. Хранение секретов и безопасность
- Все артефакты аутентификации хранятся в директории `data/auth/`.
- В `.gitignore` внесены строгие правила, исключающие попадание в репозиторий:
  - `data/auth/`, `auth-data/`
  - `*.key`, `*.crt`, `*.pem`, `*.p12`, `*.pfx`, `*.password`, `owner_password.txt`
- Доступ к эндпоинтам управления сертификатами в `admin-shell` требует обязательного заголовка с подтверждённым сертификатом владельца; прямой доступ без валидации сертификата запрещён.

---

### 4. Руководство для Владельца (Owner Workflow)

#### Шаг 1. Импорт сертификата Владельца
1. Скопируйте файл сертификата:
   `data/auth/certificates/owner.p12`
2. Откройте файл пароля:
   `data/auth/owner_password.txt`
3. Установите сертификат в ОС или браузер:
   - В Windows: двойной клик по `owner.p12` -> «Текущий пользователь» -> ввести пароль -> поместить сертификаты автоматически.
   - В браузере (Chrome / Edge): Настройки -> Конфиденциальность и безопасность -> Безопасность -> Управление сертификатами -> вкладка «Личные» -> «Импорт».

#### Шаг 2. Вход в систему
1. Перейдите по адресу:
   `https://127.0.0.1:8443/` (или `https://localhost:8443/`).
2. В появившемся окне браузера выберите установленный сертификат `Technoreboot OWNER`.
3. Система откроет главную панель управления.

#### Шаг 3. Выпуск сертификата для сотрудника
1. Перейдите в раздел меню **«Доступ (mTLS)»** (`/certificates`).
2. В блоке «Выпуск нового сертификата» укажите имя (например, `Касса 1` или `Мастерская`).
3. Нажмите кнопку **«Выпустить сертификат»**.
4. Сохраните показанный одноразовый пароль и скачайте файл `.p12`.
5. Передайте архив и пароль сотруднику для установки на рабочем компьютере.

#### Шаг 4. Отзыв сертификата
- В таблице «Зарегистрированные сертификаты» нажмите кнопку **«Отозвать»** напротив нужного сертификата.
- Отзыв вступает в силу немедленно без перезапуска контейнеров: последующие запросы с этого сертификата будут блокироваться шлюзом со статусом `403 Forbidden`.
