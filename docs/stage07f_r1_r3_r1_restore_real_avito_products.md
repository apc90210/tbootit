# Stage 07F-R1-R3-R1: Восстановление реальных товаров Авито и верификация пакетного импорта

## 1. Контекст и инцидент

В ходе предыдущей очистки базы данных от синтетических тестовых товаров (`id >= 171`) были ошибочно удалены 35 реальных записей (33 реальных товара Авито и 2 тестовые заглушки 171, 172). Перед удалением был создан полный снимок SQLite:
`data/db/technoreboot.db.bak_before_cleanup_20260910`.

В рамках этапа Stage 07F-R1-R3-R1 выполнен безопасный точечный аудит и восстановление данных:
- Без полного отката базы данных.
- Без восстановления 123 синтетических тестовых товаров `live_07f_*`.
- С сохранением всех 160 базовых товаров каталога.
- С восстановлением точных исходных числовых идентификаторов (`296..328`, `171`, `172`).
- С сохранением внешних связей `product_external_listings`.
- С устранением недочета в парсинге фото `extractBestUrlFromSrcset` в расширении Chrome.
- С внедрением строгого инварианта нулевого загрязнения: `REAL_PRODUCT_SET_BEFORE == REAL_PRODUCT_SET_AFTER`.

## 3. Архитектура безопасности очистки тестов

1. **Запрет широких удалений по диапазону:**
   Любая логика очистки вида `id >= N` строго запрещена.
2. **Точечное удаление по идентификаторам сессии:**
   Тестовые скрипты верификации обязаны регистрировать ID созданных ими сущностей (`created_test_ids`) и проверять детерминированный префикс (`live_07f_`).
3. **Строгий инвариант целостности:**
   Во всех скриптах и тестах фиксируется множество реальных товаров до теста (`REAL_PRODUCT_SET_BEFORE`) и после теста (`REAL_PRODUCT_SET_AFTER`), с жестким утверждением:
   $$\text{REAL\_PRODUCT\_SET\_BEFORE} \equiv \text{REAL\_PRODUCT\_SET\_AFTER}$$
4. **Регрессионные тесты защиты:**
   В `avito-module/tests/test_stage07f_cleanup_safety.py` реализован набор тестов, доказывающий:
   - Синтетические записи удаляются;
   - Реальные записи с высокими ID (например, 304, 305) гарантированно сохраняются;
   - Попытка удаления записи без тестового префикса отклоняется защитным барьером (`SECURITY VIOLATION`).
