# Документация: Stage 07G-R1 — Avito Import Reactivation & ID Sync

## 1. Назначение и концепция

В рамках этапа **Stage 07G-R1** регламентировано и реализовано ключевое бизнес-правило каталога и синхронизации ТехноРебут:

> **Осознанный импорт активного объявления с Авито означает, что физический товар есть в наличии.**

Если Владелец импортирует активное объявление с Авито (через расширение Chrome или интеграционный API):
- ТехноРебут воспринимает это действие как подтверждение наличия товара.
- Если товар с таким же Avito ID (`external_item_id`) уже существовал в системе, но находился в архиве, был продан, имел нулевой остаток или статус черновика (`sold/archive/0`, `draft/store/1`, `archived/0`), система **реактивирует ЭТОТ ЖЕ товар** в торговый зал (`status = "in_stock"`, `storage_location = "store"`, `quantity = 1`), логируя событие `avito_import_reactivated`.
- **Никаких дубликатов товара не создается**. Первичный ключ кросс-системной идентификации — Avito ID (`external_item_id`).

---

## 2. Ключевой инвариант: статус объявления на Авито не управляет физическим списанием

**Важнейшее изменение по отношению к предыдущей гипотезе:**
Внешние статусы Авито (`closed`, `inactive`, `archived`, `blocked`, `removed`, `rejected`, `hidden`, `suspended`) **НЕ ИМЕЮТ ПРАВА** автоматически списывать товар в архив или обнулять его физический остаток (`sold/archive/0`).

### Обоснование:
1. Объявление на Авито может быть временно снято, скрыто или заблокировано модерацией.
2. Физический товар при этом продолжает лежать на витрине или складе магазина.
3. Списание товара в статус `sold` и перемещение в `archive` допустимо только через:
   - проведение розничной продажи на кассе магазина;
   - явное ручное действие сотрудника/Владельца по списанию;
   - другие утвержденные локальные бизнес-процессы.
4. При импорте неактивного/снятого объявления обновляется только метаданное поле `ProductExternalListing.remote_status`. Физические поля `Product.status`, `Product.storage_location`, `Product.quantity` остаются неприкосновенными.

## 3. Таблица переходов состояний (Transition Matrix)

| Исходное состояние в ТехноРебут | Входящий импорт с Авито | Результат | Комментарий |
|---|---|---|---|
| Товар отсутствует | `remote_status = "active"` | Создание: `in_stock / store / 1` | Первичный импорт нового товара |
| `in_stock / store / 1` | `remote_status = "active"` | Тот же товар, сохранение `in_stock / store / 1` | Обновление полей (цена, заголовок, описание) без инфляции остатка |
| `draft / store / 1` | `remote_status = "active"` | Тот же товар -> `in_stock / store / 1` | Активация черновика в продажу |
| `sold / archive / 0` | `remote_status = "active"` | Тот же товар -> `in_stock / store / 1` | Реактивация из архива, событие `avito_import_reactivated` |
| Любой архив (`archive / 0`) | `remote_status = "active"` | Тот же товар -> `in_stock / store / 1` | Реактивация из архива, событие `avito_import_reactivated` |
| Любое состояние товара | `closed / inactive / blocked / removed / archived` | Физический остаток **не меняется**, обновляется `remote_status` | Защита от ложного списания |
| Локальный товар без Avito ID | Нет импорта с Авито | Полная валидность и независимость | Avito ID не является обязательным для локальных товаров |

## 4. Архитектура идентификации (Двухуровневый поиск)

Поиск товара при импорте объявления выполняется строго по всей базе данных без каких-либо фильтров по текущему статусу (`status`) или месту хранения (`storage_location`):

1. **Первичный поиск:**
   ```python
   ext_link = db.query(models.ProductExternalListing).filter(
       models.ProductExternalListing.external_item_id == item_id_str
   ).first()
   if ext_link:
       product = db.query(models.Product).filter(models.Product.id == ext_link.product_id).first()
   ```
2. **Резервный поиск (Fallback):**
   ```python
   if not product:
       product = db.query(models.Product).filter(models.Product.sku == f"AVITO-{item_id_str}").first()
   ```
   Если товар найден по SKU, но запись в `product_external_listings` отсутствовала, система автоматически создает/восстанавливает связь, исключая появление дубликата.

---

## 5. Защита от инфляции остатков (No Quantity Inflation)

Повторные осознанные импорты одного и того же активного объявления не увеличивают остаток:
```python
if is_reactivating:
    product.status = "in_stock"
    product.storage_location = "store"
    product.quantity = max(product.quantity or 0, 1)
else:
    if not product.quantity or product.quantity <= 0:
        product.quantity = 1
```
Если товар уже имел остаток `1` (или больше), повторный импорт сохраняет имеющийся положительный остаток (`1 -> 1 -> 1`).

---

## 6. Локальные товары (Local-Only Products)

Система полностью поддерживает товары, которые не выгружаются и не привязаны к Авито:
- Такие товары имеют стандартный внутренний ID, артикул (SKU) и штрихкод.
- Они продаются через кассу, участвуют в складском учете и ремонтах.
- Отсутствие `external_item_id` или префикса `AVITO-*` не вызывает никаких ошибок и не затрагивается процедурами импорта с Авито.
