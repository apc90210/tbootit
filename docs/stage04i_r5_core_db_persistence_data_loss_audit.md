# Stage 04I-R5 Core DB Persistence and Data-Loss Audit Documentation

## Overview
This document records the comprehensive audit and resolution of database persistence and data isolation for Stage 04I-R5 of project "Technoreboot".

---

## 1. Discrepancy Analysis & Root Cause Determination
- **Observed Inconsistency:**
  - Stage 04I-R3 report reported 66 total products (59 with barcode, 7 without barcode).
  - Stage 04I-R4 report reported 53 total products (1 with barcode, 52 without barcode).
- **Empirical Root Cause:**
  - During Stage 04I-R3 execution, `validate_stage04i_r3.py` created 6 transient test products (IDs 61-66) and sales (IDs 40-43) in the live database `/data/db/technoreboot.db`.
  - Immediately following runtime validation in Stage 04I-R3, the test suite `docker compose exec core pytest` was executed.
  - Test fixture in `core/tests/test_product_filter_options_cascading.py` invoked `Base.metadata.drop_all(bind=engine)` directly on `app.database.engine`. Because pytest inside the container inherited `DATABASE_URL=sqlite:////data/db/technoreboot.db`, this call dropped all tables in the live database file on host disk `C:\tbootit\data\db\technoreboot.db`.
  - The remaining 53 products and 33 sales in Stage 04I-R4 were the exact test seed records generated by `pytest` at the conclusion of Stage 04I-R3.
- **Docker Persistence Status:**
  - Docker volume mount `./data/db:/data/db` is a valid host bind mount (`C:\tbootit\data\db` -> `/data/db`). Container recreations (`docker compose up --force-recreate`) DO NOT lose database state.

---

## 2. Test Suite Database Isolation Fix
- **Implementation:**
  - Created `core/tests/conftest.py` which sets `os.environ["DATABASE_URL"] = "sqlite:////tmp/pytest_core_isolated.db"` before any test suite loads `app.database`.
  - Added session-scoped teardown to clean up `/tmp/pytest_core_isolated.db`.
  - Created `core/tests/test_database_persistence_config.py` to assert that pytest runs against isolated database `/tmp/pytest_core_isolated.db` and never touches `/data/db/technoreboot.db`.
